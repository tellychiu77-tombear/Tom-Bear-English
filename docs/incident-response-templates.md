# Incident Response Templates — 各類事件溝通範本

> **目的**：當事故發生時（個資外洩、系統中斷、Key 外洩等），有事先準備好的範本可直接套用，避免「慌張中起草訊息」造成更大傷害。
> **撰寫日期**：2026-05-27
> **適用範圍**：所有 Phase（出事就生效）
> **規範來源**：[`pii-protection-plan.md`](./pii-protection-plan.md) §6、[`disaster-recovery-runbook.md`](./disaster-recovery-runbook.md)、[`encryption-key-rotation-runbook.md`](./encryption-key-rotation-runbook.md)
> **重要**：本文件範本未經律師審閱。**第一次真正要用**前請花 NT$5,000-15,000 請律師快速 review。

---

## 0. 為什麼需要範本

### 0.1 黃金 1 小時原則

事故發生後第 1 小時是最關鍵的：

- 早 30 分鐘通知 = 信任 +30%
- 晚 6 小時通知 = 信任 -50%、可能被認定「隱匿」

但第 1 小時你**通常很慌**。要邊處理事故邊起草溝通文件 → 結果兩件都做不好。

**範本的價值**：8 成的字句已寫好，只要 fill in (時間、範圍、影響人數) 即可發出。

### 0.2 通知對象優先序

| 優先 | 對象 | 通知方式 |
|------|------|--------|
| 1 | 內部員工（少數）| 口頭 + 內部 Slack/LINE |
| 2 | 受影響的家長 / 老師 | Email + LINE 個別通知 |
| 3 | 主管機關（依事件性質）| 公文 + Email |
| 4 | 媒體（被動回應）| 統一發言 |

## 1. 內部溝通範本

### 1.1 事故初次告知（給合作夥伴 / 員工）

**情境**：你發現事故時，必須在 30 分鐘內讓相關員工知道。

**LINE / Slack 文字（短版）**：

```
緊急通知 ⚠️

剛偵測到 [事故類型摘要]，目前正在 [處理動作]。

對員工的影響：
- [是否需要員工做什麼，例：先暫停 X 操作]
- [是否需要員工知道什麼，例：今天不要對家長提及 Y]

下次更新：[時間，建議 1-2 小時內]

如有疑問請直接打給 Telly 0XXX-XXX-XXX。
```

**Email（長版）**：

```
主旨：[緊急] 系統事故通知 - YYYY-MM-DD HH:MM

[員工稱呼]：

我是 Telly。剛剛 HH:MM 我們系統發生了 [事故類型 — 一句話]。

目前狀況：
- 影響範圍：[具體哪些功能 / 哪些客戶]
- 處理狀態：[正在做什麼]
- 預計恢復：[時間估計 — 不確定請說不確定]

需要你協助的事：
1. [具體請求]
2. ...

⚠️ 在我們對外正式公告前，請暫時不要：
- 對家長 / 客戶提及此事
- 在社群媒體 / LINE 群組討論
- 對其他補習班同業透露

完整事故進度更新將於 HH:MM 給你下一封 email。

任何疑問請直接打給我：0XXX-XXX-XXX

Telly
```

### 1.2 事故解除後內部 wrap-up

```
主旨：事故解除 - YYYY-MM-DD 事故 wrap-up

[員工稱呼]：

YYYY-MM-DD HH:MM 發生的 [事故] 已於 HH:MM 恢復。

最終狀況：
- 影響範圍：[最終確認]
- 影響時長：N 分鐘 / 小時
- 影響家長 / 學生人數：N 位
- 已通知對象：[誰已收到正式通知]

接下來的工作：
1. 我會在 7 天內寫一份完整 incident report 給你
2. [後續補救動作，例：補登 X 資料]
3. 流程改進：[會做什麼避免再發生]

請繼續用平常方式回應家長與學生。如果有家長主動問起此事，請按以下回覆：
[統一口徑，例：「系統有短暫維護，已恢復，您的資料完全安全」]

感謝在事故期間的配合。

Telly
```

## 2. 給家長 / 客戶的通知

### 2.1 個資外洩通知（最嚴重的一種）

**情境**：encryption_key 外洩或 production DB 被入侵，可能影響學生個資。

**Email（長版 — 法律建議的格式）**：

```
主旨：【重要】關於系統資料安全事件通知 - YYYY-MM-DD

親愛的 [家長稱呼] 您好：

我是湯貝爾英文學校的負責人 [Telly]。

很抱歉必須以這封信告知您：YYYY-MM-DD HH:MM，我們發現本系統發生資料安全事件，可能影響您與孩子的部分個人資料。

【事件說明】
- 發生時間：YYYY-MM-DD HH:MM
- 發現時間：YYYY-MM-DD HH:MM
- 事件性質：[簡單描述，例：資料保護金鑰可能外洩]
- 可能影響的資料：學生姓名、家長聯絡電話、過敏資料等

【影響範圍】
依個資法第 12 條規定，雖然外部攻擊者實際取得資料的可能性低，我們仍主動通知您。

【我們已採取的措施】
1. 已於 YYYY-MM-DD HH:MM 立刻更換資料保護金鑰，重新加密所有資料
2. 強化內部存取流程
3. 持續監控異常存取
4. [如有其他具體動作]

【您可以做的事】
1. 如果您近期收到陌生來電或詐騙訊息，請特別留意
2. 不要對自稱「湯貝爾老師」的電話透露個資（我們的老師不會主動電話索取資料）
3. 如有任何疑問，請聯絡我們：[Email / 電話]

我們將於 [預計日期] 提供完整的事件處理報告。

對於此事件造成您的擔憂，我們致上最誠摯的歉意。

湯貝爾英文學校
負責人：Telly Chiu
聯絡：[email] / [phone]
日期：YYYY-MM-DD
```

**⚠️ 送出前必做**：
1. **律師最終 review**（即使你已用此範本，每次具體事件律師需 review 措辭）
2. **時效**：個資法要求「及時通知」，實務上 **72 小時內** 是業界標準
3. **送出方式**：Email + 系統公告。重大客戶建議再加電話通知
4. **保留紀錄**：每封通知保留發送紀錄至少 5 年

### 2.2 服務中斷通知（較輕微）

**情境**：系統當機 30 分鐘以上 / 重要功能無法使用。

**LINE 群組 / 系統公告**：

```
親愛的家長您好：

我們的系統目前發生短暫的技術問題，影響：
- [影響範圍]

預計恢復時間：[時間]

孩子的學習與接送照常進行，僅是線上系統暫時無法登入。

造成不便，敬請見諒。如有急事請直接電話聯絡：[電話]

湯貝爾英文學校
```

**事後（恢復後 1-2 小時內）**：

```
親愛的家長您好：

剛才 HH:MM 至 HH:MM 的系統技術問題已完全恢復。

期間您可能遇到的不便：
- 無法登入查看孩子聯絡簿
- 無法請假
- 無法收到接送通知

所有資料完全沒有遺失，今天的接送 / 點名等紀錄都已備齊。

感謝您的耐心。

湯貝爾英文學校
```

### 2.3 計畫性維護預告（Phase A migration 套用前用）

**情境**：Phase A migrations 要上 production 前 1 週發出。

```
親愛的家長您好：

為持續改善系統，我們將於 YYYY-MM-DD 晚上 21:00 至 22:00 進行系統維護。

維護期間：
- 系統將短暫無法登入（約 60 分鐘）
- 接送 / 點名等實體流程不受影響（老師會用紙本備援）

維護內容（簡單版）：
- 系統架構優化，提升查詢速度與安全性
- 新增更好的個資保護機制

維護後您會感受到：
- 登入速度更快
- 部分介面有調整（細節參見下次操作指南）

如有疑問請隨時聯絡：[email] / [phone]

湯貝爾英文學校
```

## 3. 給主管機關的通報

### 3.1 個資法第 12 條通報（重大個資事件）

**情境**：個資外洩確認或有合理懷疑，且影響 500 人以上 / 含特殊個資（健康、犯罪等）。

**通報對象**：個人資料保護委員會（個資法 2023 修法後成立）

**格式**：公文式，需具公司大頭章。建議格式：

```
受文者：個人資料保護委員會
發文日期：中華民國 YYYY 年 MM 月 DD 日
發文字號：[湯貝爾發文字號]
速別：最速件
密等：限閱

主旨：本機構發生個人資料外洩事件，依個資法第 12 條通報。

說明：
一、事件發生時間：YYYY 年 MM 月 DD 日 HH 時 MM 分。
二、事件發生情形：（簡述）
三、影響範圍：受影響當事人約 N 人，涉及資料項目包括：
    1. 學生姓名（直接識別）
    2. 家長聯絡電話（直接識別）
    3. [其他項目]
四、本機構已採行措施：
    1. （列點）
    2. ...
五、已通知當事人之情形：
    （說明通知方式、時間、預估完成日）
六、聯絡人：
    姓名：Telly Chiu
    電話：[phone]
    Email：[email]

正本：個人資料保護委員會
副本：[視情況，例：教育部補習教育群組]

機構大章：[湯貝爾大章]
負責人簽章：[簽名]
```

**⚠️ 重要**：實際格式請依個資保護委員會公布的「個人資料外洩通報處理流程」最新版本，本範本僅為架構參考。

### 3.2 教育部 / 教育局的補習班通報

**情境**：補習班管理辦法相關事件（學生健康 / 安全 / 重大個資事件）

```
受文者：[縣市] 政府教育局 (或補習教育主管機關)
發文日期：YYYY 年 MM 月 DD 日

主旨：本班發生 [事件性質] 事件通報。

說明：
一、事件發生時間：YYYY-MM-DD HH:MM
二、事件性質：（簡述）
三、影響學生人數：N 位
四、本班已採行措施：（列點）
五、預計後續處理：（列點）
六、聯絡人：負責人 Telly Chiu，[電話]

機構章：[湯貝爾大章]
```

## 4. 對媒體的應對（被動）

### 4.1 媒體來電詢問的標準回覆

**情境**：如有記者打電話、傳訊息詢問事件細節。

**第一道防線：別亂講**

```
「您好，我是湯貝爾的 [Telly]。我們已將事件詳細資訊通知所有受影響家長與主管機關。

我們會在 [時間] 提供完整的書面說明，目前不方便在電話中說明細節，請您理解。

如您有具體問題，請 email 至 [email]，我們會書面正式回覆。

謝謝您的理解。」
```

**不要說的話**：

- ❌「不知道」（顯得不負責）
- ❌「事件不嚴重」（任何降級事實的說法都會被截取）
- ❌「不會有下一次」（無法保證的事不要承諾）
- ❌「都是 [某廠商] 的錯」（推卸責任會反咬一口）
- ❌「不要寫這個」（記者可能就因為你說這句寫了）

### 4.2 媒體書面正式回覆

**寄出前必經律師 review**。範本架構：

```
親愛的 [媒體記者] 您好：

針對 YYYY-MM-DD 發生於湯貝爾英文學校的 [事件名稱]，本校說明如下：

一、事件性質：
   （與通知家長的版本一致，不要不同說法）

二、影響範圍：
   （與通報主管機關的版本一致）

三、本校採取的措施：
   1. 立即 [動作 1]
   2. 已於 [時間] 完成 [動作 2]
   3. 後續將 [動作 3]

四、給家長的承諾：
   （簡短，例：強化資料保護機制、定期安全 audit）

五、聯絡方式：[email / phone]

對此事件造成的擔憂，我們致上歉意，並承諾持續強化系統安全。

湯貝爾英文學校
負責人：Telly Chiu
YYYY-MM-DD
```

## 5. Post-mortem（事後檢討）

事故結束後 7-14 天內，寫一份內部 post-mortem，**不對外發布**。存進 `docs/incidents/YYYY-MM-DD-{event-name}.md`。

```markdown
# Incident Post-mortem: [事件名稱]

## 摘要
- 事故時間：YYYY-MM-DD HH:MM ~ HH:MM
- 持續時長：N 分鐘 / 小時
- 影響範圍：[誰受影響、多少人]
- 嚴重度：🔴 高 / 🟡 中 / 🟢 低
- 負責人：Telly

## 時間軸（精確到分鐘）

| 時間 | 動作 / 發現 |
|------|-----------|
| HH:MM | [偵測到問題] |
| HH:MM | [採取行動 1] |
| HH:MM | [...] |
| HH:MM | [完全恢復] |

## 根因分析（5 Whys）

第 1 個 Why：[為什麼這件事發生？]
→ 答：

第 2 個 Why：[為什麼會這樣？]
→ 答：

[繼續到第 5 個 Why，或回答不出來為止]

最終根因：[一句話]

## 為什麼沒早點發現

- 監控有沒有 alert？沒有 → 為什麼？
- 我有沒有忽略警訊？是 → 哪個警訊？

## 對策 — 預防再次發生

| # | 對策 | 何時實施 | 負責 |
|---|------|---------|------|
| 1 | ... | YYYY-MM-DD 前 | Telly |
| 2 | ... | ... | ... |

## 對流程的改進

| # | 流程改動 | 影響的文件 |
|---|---------|----------|
| 1 | ... | xxx.md §N |
| 2 | ... | ... |

## 學到的事（給未來的自己）

[3-5 句教訓]

## 紀錄者
Telly，YYYY-MM-DD
```

## 6. 範本使用 checklist

當你必須真實使用任一範本時，跑一遍：

- [ ] 範本內所有 `[填入]` 都填好
- [ ] 時間都正確
- [ ] 影響範圍是「精確的、可驗證的」數字（不是「大概很多」）
- [ ] 律師有 review（個資外洩、媒體應對、主管機關通報尤其需要）
- [ ] Cross-check 各通知對象拿到的訊息**一致**（不要對家長說 A、對主管說 B）
- [ ] 保留所有發送紀錄
- [ ] 寫進對應的 incident report
