## 0. 為什麼現在寫這份（你還在出差）

這份手冊**不是要你現在做**。等 Phase D 完成後 6-12 個月才用。

那為什麼現在寫？三個理由：

1. **避免「臨時決定」**：到時候你會被各種客戶需求拉著走，沒時間冷靜思考。現在思路清楚，先把架構定下來。
2. **指導 Phase A-D 的取捨**：知道「未來怎麼賣」會反過來影響「現在怎麼做」— 例如 Phase A 的 RLS / 加密規格直接影響你能不能對外承諾「資料安全」。
3. **可信度建構**：你跟律師、跟潛在客戶談時，能掏出一份完整 plan 比口頭講可信 10 倍。

## 1. 商業模式抉擇 — 三種模式的最終比較

v3.0 報告與 week0-tech-decisions.md 把這個決定**擱置到 Phase D**。本文件第 12 章會幫你做出決定。

先複習三個選項：

### 1.1 純 SaaS 訂閱

```
客戶得到：軟體使用權
你得到：月費
資料：客戶擁有，你只能看匿名統計
合約：Software License Agreement
```

優點：法律簡單、好複製
缺點：你拿不到實用研究資料，「實體派」軌道走不下去

### 1.2 軟體加盟（virtual franchise）

```
客戶得到：品牌 + 軟體 + SOP + 培訓
你得到：加盟金（一次性）+ 權利金（月）
資料：因為「使用品牌」客戶讓出更多權利
合約：受公平交易法管的加盟合約
```

優點：能訂高客單價
缺點：合約極複雜、需主管機關報備、補教加盟在台灣已是夕陽

### 1.3 研究合作社（research consortium） ⭐ 推薦

```
客戶得到：軟體 + 跨校 benchmark 報告 + 教育研究分享
你得到：月費 + 合法數據使用權 + 研究素材
資料：客戶仍擁有，但雙方協議匿名統計可用於跨校研究與發表
合約：SaaS + Data Use Addendum（DPA 強化版）
```

優點：
- ✅ 雙贏（客戶得到產業 benchmark，你得到研究資料）
- ✅ 法律基礎清楚（個資法第 16 條學術研究目的）
- ✅ 跟 Telly 的長期實體派軌道一致

缺點：
- ⚠️ 合約比純 SaaS 複雜一點
- ⚠️ 需主動產出 benchmark 報告（每季？每半年？）

**本文件後續以「研究合作社」模式為主軸。**

## 2. 目標客戶輪廓（ICP — Ideal Customer Profile）

不是所有補習班都該成為你的客戶。把不適合的對象提前排除可省大量時間。

### 2.1 一級目標（最先接觸）

| 條件 | 為什麼這樣 |
|------|----------|
| 學生數 80-200 人 | 你的中型規模，定價模型最 fit |
| 經營者年齡 35-55 歲 | 對科技開放但不追潮流；願意付月費 |
| 自有空間 ≥ 3 年 | 表示已過存活期，有穩定金流 |
| 主任 / 老闆是同一人 | 決策快，不需「報告董事會」 |
| 願意花時間跟你深聊 1 小時 | 推廣需要 |
| 跟 Telly 有 1-2 度人脈關係 | 信任建立成本低 |

### 2.2 二級目標（第二批接觸，6-12 個月後）

| 條件 | 備註 |
|------|------|
| 學生數 200-400 人 | 更大但流程複雜 |
| 連鎖補教（2-3 個分校）| 系統整合度需求高 |
| 幼兒園 | 模組設計類似但對「接送通知」需求更強 |

### 2.3 不要接觸的（至少前 24 個月）

| 條件 | 為什麼避開 |
|------|----------|
| 超大型補習班（500+ 學生）| 客製化需求多、合約複雜，會把你拖累 |
| 1-50 學生的小型 | 預算太低、流失率高 |
| 完全沒科技基礎（連 LINE 都不熟）| Onboarding 成本太高 |
| 跟老闆談他都「我考慮看看」、拖延的 | 不會成交 |
| 個性挑剔型客戶 | 第一批客戶很重要，避開難相處的 |

### 2.4 你已知道的潛在第一批清單（待填）

Telly 自己填這份名單，不用 Claude 想：

```
1. [補習班名] - 規模 X 學生 - 跟我的關係 - 為什麼 fit
2. ...
3. ...
4. ...
5. ...
```

⚠️ 至少要有 5 家在這名單上才能啟動 §3 推銷流程。少於 5 家代表你還沒準備好對外（先擴大同業人脈）。

## 3. 銷售漏斗 — 從接觸到簽約

```
[潛在客戶名單 N 家]
        ↓ -50%
[同意 1 對 1 介紹會面]
        ↓ -30%
[同意試用 3 個月]
        ↓ -30%
[試用結束願付月費]
        ↓
[簽約客戶]
```

預期轉換率：5 家潛在 → 1 家簽約（20% 整體）。

### 3.1 階段 1：個別介紹（1 對 1 對話，30-60 分鐘）

地點：對方補習班 / 咖啡廳，**不要視訊**（信任度遠低於面對面）。

**對話結構（推薦時間分配）**：

```
(5 min) 寒暄 + 業界八卦（建立同行 rapport）
(10 min) 問他：「你補習班目前最大的營運痛點是什麼？」（聆聽，不要立刻推銷）
(15 min) 你的故事：「我自己也是補習班經營者，因為這些痛點所以做了一套系統」
(20 min) 簡單 demo：手機打開系統，秀 3 個你覺得對方會有 reaction 的功能
(10 min) 試用邀請：「我們現在還在做產品打磨，想找 3-5 家補習班一起測。前 3 個月免費，我們也會分享產業 benchmark 給你」
(收尾) 加 LINE + 約下一步
```

**對話禁忌**：

- ❌ 不要一開始就講「AI」「研究」「實體派」（會嚇跑同業）
- ❌ 不要說你的補習班「比他好」（即使是真的）
- ❌ 不要提具體價格（等試用結束才談）
- ❌ 不要承諾「能解決他所有問題」

### 3.2 階段 2：試用邀請（試用 3 個月）

成功完成階段 1 對話、對方表達興趣後：

#### 試用方案內容

| 項目 | 細節 |
|------|------|
| 試用期 | 3 個月（90 天） |
| 費用 | 完全免費 |
| 對方付出 | 提供 1 位種子老師（每週 30 分鐘 check-in）|
| 上限 | 50 學生（避免你的 AI 成本失控）|
| 資料協議 | 試用合約 + 簡化版 DPA（律師事前準備）|
| 試用後 | 同意付費就繼續、不同意則資料完整 export 給對方 + 帳號永久關閉 |

#### Onboarding 流程

詳見 §6。第一批客戶**你親自帶**，不要委派助理。

### 3.3 階段 3：試用結束「轉付費」對話

第 75 天起（試用結束前 15 天）開始：

**Step 1：產出試用報告**

給對方一份 1-2 頁簡報，內容：

```
過去 3 個月 [補習班名] 在 Intelligent Kids 平台的使用數據
- 老師寫聯絡簿次數：N 次
- 平均寫一份耗時：X 分鐘
- 家長閱讀率：Y%
- 老師覺得每天省下時間：Z 分鐘
- VS 跨校 benchmark 中位數：[比較]
```

**Step 2：1 對 1 對話（45 分鐘）**

```
(5 min) 重述試用 KPI 數據
(15 min) 問對方：「實際用了 3 個月，你覺得這套系統對你補習班幫助多大？」
(15 min) 介紹付費方案（§4 定價）+ 簽約後的權益
(10 min) 處理 objections（§8）
(收尾) 給 7 天考慮 + 約下次見面簽約
```

**Step 3：簽約**

合約樣板由律師起草（見 §7）。重點條款：

- 服務內容（包含什麼、不包含什麼）
- 價格與付款方式
- 資料協議（DPA）
- 終止條款（任一方可 30 天 notice 終止）
- 違約處理
- 個資與保密

## 4. 定價策略

### 4.1 基準定價（v3.0 §8 沿用 + 微調）

| 規模 | 學生數 | 你的成本 (TWD/月) | **建議月費** | 毛利 | 毛利率 |
|------|--------|--------------------|-----------|------|-------|
| **Starter** | 50-100 | NT$2,500-3,500 | **NT$6,000** | ~NT$3,000 | 50% |
| **Growth** | 100-200 | NT$4,000-5,500 | **NT$12,000** | ~NT$7,000 | 58% |
| **Scale** | 200-400 | NT$7,000-10,000 | **NT$24,000** | ~NT$15,000 | 63% |

**比 v3.0 §8 略調**：起手價拉高（NT$4,500 → NT$6,000），因為加入研究合作社的 benchmark 報告附加價值。

### 4.2 收費公式（簡單版）

```
月費 = base_price + (學生數 - threshold) × per_student
```

- Starter (≤100 學生)：NT$6,000 固定
- Growth (101-200)：NT$6,000 + (學生數 - 100) × NT$60
- Scale (201+)：NT$12,000 + (學生數 - 200) × NT$60，至 NT$24,000 封頂

### 4.3 折扣策略

| 情境 | 折扣 |
|------|------|
| 年付（12 個月一次付）| 10% off（節省 NT$7,200/年 Growth 級 → 你拿一筆現金可投資） |
| 雙年合約 | 15% off |
| 同業推薦（每介紹 1 位簽約客戶）| 推薦人 next 月 50% off |
| Telly 個人關係（前 3 位客戶）| 第一年 50% off（換取早期見證）|
| 公立 / 偏鄉補教 | 70% off 永久（社會回饋）|

⚠️ 折扣**不要超過 30% 從定價**（避免後續客戶覺得你價格亂）。

### 4.4 Add-on 加值服務（單獨計價）

| 服務 | 一次性 / 月費 |
|------|------------|
| 從舊系統匯入歷史資料 | NT$5,000-15,000 一次性（依資料量）|
| 客製化欄位（學員特殊資訊）| NT$3,000/欄位 一次性 |
| 員工現場 onboarding 訓練 | NT$3,000/小時 + 交通費 |
| 客戶專屬報表 | NT$2,000/月 |
| 假日 / 晚上技術支援 | NT$1,500/月 |
| 個資諮詢（小規模 q&a）| 包含在月費；大規模 NT$5,000/小時 |

### 4.5 何時提價

**不要** Phase D 結束就提價。**前 24 個月維持定價以累積客戶**。

提價的觸發條件：

- 已有 10+ 付費客戶
- 月流失率 < 5%
- AI 化已穩定運行 6 個月

提價方式：新客戶 +20%，舊客戶維持原價（grandfather clause）— 鎖住老客戶忠誠。

## 6. 客戶 Onboarding 完整流程（簽約後 30 天）

### Week 1: 技術 onboarding

| Day | 動作 | 負責 |
|-----|------|------|
| D1 | 對方提供：補習班基本資料、班級結構、學生名單、員工名單 | 客戶 |
| D1 | 你建立新 tenant（migration 001 那種，新增一筆 tenants 記錄）| 你 |
| D2-D3 | 你 / 助理用 admin 帳號批次匯入學生（或對方自己匯）| 你 + 客戶 |
| D4 | 對方主管 + 1 位老師 onboarding 訓練（2 小時，現場或視訊）| 你 |
| D5 | 對方其他老師「軟啟動」— 自己摸索，你 stand by | 客戶 |

### Week 2: 真實使用

- 對方在你的監督下用 1 週
- 每天結束你查一次 operational_events 看有沒有異常
- 任何 bug 24 小時內回應

### Week 3-4: 全面上線

- 邀請對方家長加入
- 老師輔助家長註冊
- 每週 1 次 30 分鐘 check-in（前 4 週是這個頻率，之後降為每月 1 次）

### 30 天評估

簽 30 天「滿意保證」— 不滿意可全額退費 + 資料完整 export。讓對方無壓力試用。

⚠️ 這個保證對 retention 有極大幫助 — 知道「不滿意可退」反而讓對方更願意付費。

## 7. 合約與法律準備

### 7.1 律師關係

⚠️ 第一個外部客戶簽約前 1 個月，**必須**找熟悉教育產業的律師：

- 預估費用：起草合約樣板 NT$30,000-60,000（一次性）
- 後續每年顧問費 NT$15,000-30,000
- 推薦人脈：透過補教協會、商業夥伴介紹

### 7.2 必備合約

| 合約 | 對象 | 起草 / 維護 |
|------|------|----------|
| 服務合約（SaaS Agreement）| 客戶補習班 | 律師起草、Telly 維護 |
| Data Processing Agreement（DPA）| 客戶補習班 | 律師起草 |
| 試用合約 | 試用期間 | 簡化版 SaaS Agreement |
| Telly 與雇員的保密協議（NDA）| 員工 | 律師起草 |
| 隱私政策（線上公開）| 公眾 | 律師起草 + 公佈在 landing page |
| 服務條款（Terms of Service）| 公眾 | 律師起草 + 公佈 |

### 7.3 個資保險

- 第 3 個外部客戶後購買
- 中小企業個資險 500 萬保額：NT$15,000-50,000/年
- 含個資外洩處理費 + 第三方索賠

## 8. 常見 objections 與回應

### 8.1 「我已經用了 OneClass / 寶貝事務所」

**回應**：「那很好，他們解決了基礎管理。我們不是要取代他們的核心，我們是加上他們**沒做**的東西 — AI 寫聯絡簿、跨校 benchmark 比較。你可以兩個並用 3 個月看看。」

### 8.2 「我們補習班規模小，用不到這麼複雜的」

**回應**：「實際上規模小才更需要 — 老師人力少，每省 30 分鐘行政時間就是多一節課的價值。我們 Starter 方案就是為 50-100 學生設計的，不貴。」

### 8.3 「家長個資怎麼保護？外洩了怎麼辦？」

**回應**：（從 pii-protection-plan.md 拿來）「我們有九層防禦：欄位加密、Row-Level Security、存取日誌、5 年內定期 key rotation、季度安全 audit。我可以給你看完整文件。如果真的外洩，我們有保險。」

⚠️ 這是補教老闆最常問的問題 — 你答得專業就贏 50%。

### 8.4 「我們資料想自己擁有」

**回應**：「資料本來就是你們的，合約裡明寫。我們只能在『匿名統計研究』前提下分析跨校資料，且需要你同意。任何時候你想終止合作，我們會把你的完整資料 export 給你 + 從我們 DB 永久刪除。」

### 8.5 「貴。你的對手只收 NT$X」

**回應**：「你算過老師每天省下的時間嗎？若 1 位老師每天省 30 分鐘 × 22 天 × 時薪 NT$400 = 每月省 NT$4,400。我們 Growth 方案 NT$12,000，等於你的 3 位老師每月一起省 NT$13,200 — 已經回本。」

⚠️ 用 ROI 角度而不是「便宜」角度回應。

### 8.6 「我老婆/合夥人不同意換系統」

**回應**：「完全理解。要不要我跟他也聊聊？或者你先用 3 個月免費試用，跑出數據後給他看，他自己會判斷。」

### 8.7 「我會跟其他補習班討論，不確定你能保密」

**回應**：「我們合約有 NDA 條款，我不會跟其他客戶聊你的資料。**但**跨校 benchmark 是匿名的 — 你會看到『跨校老師寫聯絡簿平均時長』，但不知道是哪家。」

## 9. 客戶留存 — 不只賣，要留住

簽約只是開始。SaaS 業務的真實價值在於**月經常性收入（MRR）的累積**。

### 9.1 churn 預警指標（每月看）

從 `operational_events` 撈：

- 該客戶老師登入頻率比上月下降 > 30% → 紅燈
- 該客戶聯絡簿填寫筆數下降 > 50% → 紅燈
- 客戶 30 天沒主動聯絡你（沒提 bug、沒問問題）→ 黃燈（可能不在用了）
- 客戶提出 cancel 想法 → 紅燈

### 9.2 紅燈處理

立刻 1 對 1 visit（不是 email，是親自去拜訪）：

- 問「最近用得怎麼樣？」
- 找出他在用什麼 alternative / 為什麼降低使用
- 看是 product 問題還是「他自己離婚」這種 life event
- 提供補救方案：訓練、客製化、暫停付費（避免硬流失）

### 9.3 留存的最強武器

**季度 benchmark 報告**（研究合作社模式的核心 deliverable）：

每季發給每位客戶一份：

```
[補習班名] 2026 Q3 營運回顧
- 你的關鍵指標：
  - 老師寫聯絡簿頻率：X 次/週/老師
  - 家長閱讀率：Y%
  - 學生續班率：Z%
- 跨校 benchmark 比較：
  - 你的 X 高於 / 低於 中位數 by N%
  - 哪些是你做得好的地方
  - 哪些可以再加強
- 下一季建議行動：
  - [具體建議 3 條]
```

⚠️ 這份報告比月費本身價值更高 — 是讓客戶離不開你的關鍵。

## 11. 退場 / 轉折決策框架

不是每個 SaaS 都會成功。如果以下任一觸發，**重新評估方向**：

### 11.1 黃燈（評估但不放棄）

- 24 個月只有 2 付費客戶
- 客戶 retention < 70%（30% 客戶會流失）
- 你的時間 80%+ 在 sales / support，沒時間做產品

**做法**：暫停接新客戶 1 季，專注修產品 / 流程，再嘗試

### 11.2 紅燈（嚴肅考慮 pivot）

- 30 個月只有 1-2 付費客戶
- 自己的補習班也不用了
- 律師費 + 保險費 > 月營收

**做法**：

- **選項 A：純內部工具**：保留自家用，不對外賣，承認商業模式不通
- **選項 B：Pivot 軌道 B/C**：把累積的資料 + 經驗轉成「實體派研究」+ 講師事業
- **選項 C：完全退出**：把 codebase 開源、把資料完整刪除、結案

⚠️ 沒有「努力堅持」這個選項。市場已經告訴你答案 — 聽。

```
- Phase C 結果不夠正面
- 你回頭發現實體派軌道對你更重要

```
